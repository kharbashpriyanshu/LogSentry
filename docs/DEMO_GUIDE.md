# LogSentry v1.0.0 — End-to-End Demonstration & Evaluation Guide

**Document Version:** 1.0.0  
**Status:** Reproducible Verification & Evaluation Workflow  
**Target Audience:** SOC Managers, Cybersecurity Portfolio Reviewers, and Interview Evaluators

## 1. Executive Summary

This guide provides a step-by-step, reproducible walkthrough for evaluating LogSentry v1.0.0 as an enterprise Security Information and Event Management (SIEM) and Threat Investigation platform. By executing this demonstration, evaluators can inspect real-time log ingestion, regex and behavioral detection, automated Threat Intelligence enrichment, MITRE ATT&CK mapping, AI-assisted triage, incident lifecycle progression, immutable audit logging, and PDF/JSON reporting.

---

## 2. Prerequisites & Local Environment Preparation

1. **Clone & Install Dependencies:**
   ```bash
   git clone https://github.com/kharbashpriyanshu/LogSentry.git
   cd LogSentry
   python -m venv venv
   source venv/bin/activate  # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. **Configure Environment:**
   Ensure `.env` contains valid configuration parameters (or copy from `.env.example`).
3. **Start Backend Server:**
   ```bash
   alembic upgrade head
   uvicorn app.main:app --reload
   ```
4. **Start Frontend Dashboard:**
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   Open `http://localhost:5173` in a browser.

## 3. Separation of Platform Automation vs. Analyst Action

To ensure technical transparency, each step in this walkthrough indicates whether the action is performed automatically by the LogSentry platform or executed manually by the security analyst:

| Legend | Meaning |
| :---: | :--- |
| **`[AUTOMATED - PLATFORM]`** | Action performed autonomously by LogSentry's backend pipeline. |
| **`[ADVISORY - AI/SIEM]`** | Recommendation or strategy generated by LogSentry for human review. |
| **`[MANUAL - ANALYST]`** | Action performed by the SOC analyst in the UI or on affected infrastructure. |

## 4. End-to-End SOC Walkthrough

### Phase 1: Ingestion, Parsing & Detection
1. **`[MANUAL - ANALYST]` Ingest Demo Log Bundle:**
   * Navigate to **Alerts** (`/alerts`) in the LogSentry dashboard.
   * Click **Upload Log File** and select `sample_malicious.log` from the repository root.
2. **`[AUTOMATED - PLATFORM]` Parser & Normalization Pipeline:**
   * LogSentry's `ApacheLogParser` parses the raw HTTP strings into normalized `LogEvent` records.
   * The `DetectionEngine` evaluates incoming events against the 6 core detection rules (`sqli`, `xss`, `path_traversal`, `cmd_injection`, `dir_enum`, `brute_force`).
3. **`[AUTOMATED - PLATFORM]` Alert Generation & WebSocket Broadcast:**
   * When an attack pattern matches or a behavioral threshold is reached, LogSentry creates a `DetectionAlert` in PostgreSQL/SQLite and broadcasts a real-time event via WebSockets.
   * The **Alerts** table immediately populates with newly detected security events.

---

### Phase 2: Threat Intelligence & MITRE ATT&CK® Context
4. **`[AUTOMATED - PLATFORM]` Automated Enrichment:**
   * LogSentry passes the alert's `source_ip` to `EnrichmentService`, querying `AbuseIPDBProvider` and `OTXProvider`.
   * The alert is mapped to MITRE ATT&CK techniques via `MitreProvider` (`T1190`, `T1059`, `T1110`, `T1083`).
5. **`[MANUAL - ANALYST]` Review Enrichment Evidence:**
   * Click on a **"SQL Injection Attempt Detected"** alert (`T1190`, Severity: `HIGH`).
   * In the Alert Drawer, click the **Threat Intel** badge to verify the AbuseIPDB confidence score and geolocation.

---

### Phase 3: AI SOC Analyst Triage
6. **`[MANUAL - ANALYST]` Invoke AI Analysis:**
   * In the Alert Drawer, click **Analyze with AI**.
7. **`[AUTOMATED - PLATFORM]` LLM Contextual Analysis:**
   * `AIService` submits the alert payload, evidence dictionary, and enrichment context to the configured LLM provider.
8. **`[ADVISORY - AI/SIEM]` Review AI Output:**
   * Inspect the returned **Executive Summary**, **Attack Chain**, and **Containment Strategy** (`ContainmentAction` items with `Immediate`/`High` priority, concrete action steps, and technical justifications).

---

### Phase 4: Incident Correlation & Investigation
9. **`[MANUAL - ANALYST]` Correlate Alert into an Incident:**
   * Notice that the same attacker IP also triggered a **Directory Enumeration Attempt** (`T1083`).
   * Navigate to **Incidents** (`/incidents`) and click **Create Incident**.
   * Title: *"Multi-Stage Web Recon & SQL Injection Campaign"*, Severity: `HIGH`, Priority: `P2`.
   * Attach both the SQL Injection alert and Directory Enumeration alert to the incident.
10. **`[MANUAL - ANALYST]` Start Investigation & Collaborate:**
    * Click **Start Investigation** (status changes from `open` to `investigating`).
    * Assign the incident to an analyst.
    * Enter an investigation note in the comments box: *"Confirmed gobuster user-agent followed by UNION SELECT parameter. Initializing firewall containment."*

---

### Phase 5: Containment, Eradication & Resolution
11. **`[MANUAL - ANALYST]` Execute External Containment:**
    * *Note: LogSentry does not automatically modify firewalls.*
    * The analyst manually applies a drop rule for the attacker IP on the enterprise firewall/WAF as recommended by the AI containment strategy.
    * In LogSentry, click **Contain** (status changes to `contained`).
12. **`[MANUAL - ANALYST]` Resolve Incident:**
    * After verifying database audit logs confirm 0 successful injection queries, click **Resolve** (status changes to `resolved`).

---

### Phase 6: Forensic Audit Trail & Reporting
13. **`[AUTOMATED - PLATFORM]` Inspect Immutable Timeline Log:**
    * Open the Incident Timeline to inspect the chronological audit trail (`TimelineEventModel`):
      * `CREATED` — Incident creation timestamp.
      * `STATUS_CHANGED` — Transitions (`open` → `investigating` → `contained` → `resolved`).
      * `COMMENTED` — Persistent investigation notes.
14. **`[MANUAL - ANALYST]` Export Executive Compliance Report:**
    * Navigate to **Reports** (`/reports`).
    * Click **Generate PDF Report** to export the official SOC Incident & Executive Summary PDF document for compliance archiving.
